# 开发指南

## 功能概述

OpenAN 知识服务提供文档知识库与图谱知识库、检索流程编排，以及基于知识库的问答能力。仓库包含 Knowledge Studio 前端、FastAPI 后端和部署资产。本指南面向扩展后端、新增 REST 接口、修改 Web 应用或构建部署的开发人员。面向用户的行为说明见[用户指南](用户指南.md)。

## 约束与限制

- 后端要求 Python 3.11，运行在 Linux 上；前端要求 Node.js 22。
- 主应用不暴露 `/openapi.json` 和 `/docs`。对外 OpenAPI 契约由路由表生成，并由快照测试固定。
- 路由注册顺序是 API 契约的一部分。FastAPI 按注册顺序匹配，OpenAPI 生成器也按同样顺序输出路径。组装根在兜底路由之前注册各域路由。
- 业务错误使用 RFC 9457 问题详情，媒体类型为 `application/problem+json`。成功响应的状态码由各路由声明，包括创建返回 `201`、异步受理返回 `202`、删除返回 `204`。
- `AUTH_MODE=local` 下，持会话 Cookie 的业务 `POST`、`PUT`、`PATCH`、`DELETE` 请求要求 `Origin` 或 `Referer` 的主机和端口与请求地址匹配。`AUTH_MODE=none` 关闭本地鉴权；`AUTH_MODE=gateway` 由受信任的前置网关验证身份。
- `POST /query` 在 `stream: true` 时返回 Server-Sent Events。Web 端口前的反向代理必须对该路径关闭响应缓冲。
- OpenSearch 要求 Docker Linux 主机上的 `vm.max_map_count` 至少为 `262144`。

## 环境准备

### 环境要求

| 组件 | 要求 |
| --- | --- |
| 后端运行时 | Linux 上的 Python 3.11 |
| 前端运行时 | Node.js 22 |
| 数据库 | PostgreSQL 及 pgvector，由 Compose 部署提供 |
| 搜索 | OpenSearch，由 Compose 部署提供 |
| 容器运行时 | Docker Engine 与 Docker Compose v2 |

### 搭建环境

后端命令在 `backend/` 目录执行。

```bash
python -m pip install -r requirements.txt -r requirements-dev.txt
```

前端命令在 `frontend/` 目录执行。

```bash
npm ci
```

### 验证环境

编译并检查后端，然后运行两个测试套件。

```bash
python -m compileall -q src tests
ruff check src tests
python -m pytest tests -q
python -m pytest src/ingestion/tests -q
```

启动前端开发服务器并运行单元测试。

```bash
npm run serve
npm run test:unit
```

开发页面默认是 `http://localhost:8808`，API 默认代理到 `http://localhost:8091`。可在 `frontend/.env.local` 设置 `VUE_APP_API` 指向其他后端。生产构建输出到 `frontend/dist/`。

## 使用场景：扩展后端

### 场景概述

后端改动通常涉及一个 REST 域，例如在知识库域新增接口，或新增一个域模块。后端按域组织，路由、服务、仓储和领域规则放在一起。

### 系统架构

部署时运行四个 Compose 服务：带 pgvector 的 `postgresql`、`opensearch`、`backend` 和 `web`。Web 服务提供构建后的前端，并把同域的 `/api/knowledge-service/v1` 请求转发到后端。后端拥有 REST 接口层，业务数据和向量访问 PostgreSQL，关键词检索访问 OpenSearch。知识库文件写入 `kbdata` 卷。

后端源码按域组织在 `backend/src/` 下，所有对外路径都相对于 `/api/knowledge-service/v1` 前缀。

| 模块 | 职责 |
| --- | --- |
| `system` | 健康检查、部署信息、模型与文件大小元数据 |
| `auth` | 本地账号、会话、改密与认证中间件 |
| `knowledge_base` | 知识库元数据、目录、文档、切片与图谱桥接 |
| `retrieval` | 文档检索接口与检索服务 |
| `graph` | 图谱模板、抽取、导入、图谱查询、实体与关系编辑、导出 |
| `chat` | 编排式 `POST /query` 与查询追踪 |
| `workflow` | `/workflows` 检索流程系列接口 |
| `model` | `/models` 模型注册与管理 |
| `operators` | 算子注册、发布、可见性与模板 |
| `operator_api` | 提供给算子的沙箱接口 |
| `ingestion` | 解析、切分、向量化与索引写入流水线 |
| `parsing` | 文档解析器与块切分 |
| `engine` | 共享引擎服务：网关、检索证据、工具 |
| `infrastructure` | 数据库、搜索、HTTP、文件系统、日志、缓存、国际化 |
| `shared` | 前缀、切片结构、错误模型与问题详情 |

组装根是 `backend/src/http_api.py`，依次注册：system、知识库集合路由、检索、知识库内容路由、算子、图谱、对话查询路由、流程路由、模型路由和认证路由。兜底路由最后注册。

### 开发流程

1. 定位所属域模块，阅读其 `api.py` 或 `router.py`，以及相关的 `service/` 和 `repository/` 包。
2. 在域路由中新增或修改接口。抛出模块定义的领域错误，由共享处理器返回问题详情。
3. 如果新增域模块，在 `http_api.py` 中调用其 `build_router()`，位置在兜底路由注册之前。在既有域中插入路由时保持注册顺序稳定，因为顺序是 OpenAPI 契约的一部分。
4. 在既有测试目录中补充测试：跨域和契约测试放在 `backend/tests/`，入库流水线测试放在 `backend/src/ingestion/tests/`。
5. 运行上一节的验证命令。新增或修改路由后，保持 OpenAPI 快照测试通过。

### 接口说明

按域组织的完整 REST 接口见 [API 参考](API参考.md)。所有路径均相对于 `/api/knowledge-service/v1`。`AUTH_MODE=local` 下使用 `openan_session` Cookie 认证，错误以 `application/problem+json` 返回。

## 使用场景：修改 Web 应用

Web 应用是 `frontend/` 下的 Vue 单页项目。开发服务器运行在 `8808` 端口，API 代理到 `8091`。工作区路由为 `/#/knowledge`、`/#/graph`、`/#/flow`、`/#/chat` 和 `/#/models`。

1. 使用 `npm ci` 安装依赖。
2. 使用 `npm run serve` 启动开发服务器。
3. 使用 `npm run test:unit` 运行单元测试。
4. 使用 `npm run build` 构建生产资源，输出到 `frontend/dist/`。

Web 构建路径默认为 `/`。当 `WEB_BASE_URL` 设置为子路径时，重新构建 Web 应用，使其资源路径与部署一致。

## 构建与部署

部署资产在 `deploy/` 下。`docker-compose.yml` 定义四个服务和 `pgdata`、`osdata`、`kbdata`、`rkbdata` 数据卷；`.env.example` 列出环境变量。后端镜像由 `backend/Dockerfile` 构建，Web 镜像提供构建后的前端。

在部署主机上完成代码改动后重新构建：

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build --wait
```

健康检查与验收步骤见[用户指南](用户指南.md)。
